# 所有者工作台开发计划

**状态：W1–W5 已通过本地浏览器验收，已交付审批、回复溯源、按日工作概览和支持审批续跑的对话、跨机器知识上传与检索、记忆和技能修订及按次选模型整理，W6 已交付 IM 渠道管理，其他操作入口与整体验收待完成。** 2026-11-25 完成 W1–W6 逐提交复审并修正，暂缓事项见各复审提交说明。 2026-11-24。面向一位所有者管理一个 agentd，浏览器和服务可以在不同机器。基于阶段 A、B 的能力交付，技术栈、鉴权和构建遵循 [AGENTS.md](../../AGENTS.md)。各里程碑均包含 Go 接口、页面和本地验收。

工作台首先要让老板回答三个问题：数字员工刚才说了什么，当时给它看了什么，产生了哪些可核实的结果？首页列出待审批动作、结果待核对的投递、阻塞队列的事件和待审草稿，点击进入对应记录。主导航提供「对话」「工作记录」「知识库」「记忆与技能」「运行管理」。沿用 shadcn-admin 的列表、筛选和详情交互，详情有可复制的链接，返回时保留筛选与阅读位置。

## 首页「工作概览」（W1–W2）

参考 shadcn-admin 首页的四张摘要卡、趋势图和旁侧明细列表。页头显示运行状态，首行展示今日回复、今日 Token 用量、今日新闻推送和当前待办。下方默认展示含今天的最近 7 个自然日，每天一行列出回复条数、token 用量、完成推送的新闻消息条数，可点选指标看趋势或切换到近 30 天。点击「查看今日活跃对话」可进入「按对话查看」。右侧列出待审批和异常事件，页头提供「上传文件」快捷入口。窄屏把待办放在趋势图之前。[参考首页](https://shadcn-admin.netlify.app/)

| 首页指标 | 统计口径 | 点击后的明细 |
| --- | --- | --- |
| 今日回复 | 按首次成功提交的时间和稳定回复标识，统计面向会话的正式回答。模型最终文本与对应的投递记录只计一次。发送重试、进度提示、后台通知和定时群发不增加回复数。平台投递状态单独展示 | 当天逐条回复，含原会话、时间、运行和投递状态 |
| 今日活跃会话 | 当天有用户输入或正式回复的会话，按作用域和会话标识去重。后台整理和仅有定时推送的会话不计入 | 当天有交互的会话列表 |
| 今日 Token 用量 | 按实际模型调用及时间汇总已报告的输入、输出和总用量，包含工具多步调用、后台整理和新闻业务中的模型调用。实际重新调用会产生新用量，同一次调用的重复回执只计一次 | 按模型、执行器、用途和运行查看调用明细，能看到用量来自哪里 |
| 今日新闻推送 | 按 Outbox 正式新闻消息首次确认为 sent 的日期和唯一投递 ID 计数。同一条重试只计一次，分成两条且均确认送达则计两条；测试消息、待投递、失败及结果未知单列 | 查看当天的新闻消息、对应批次、所含报道、接收渠道和回执，注明平台受理或人工核对 |
| 当前待办 | 统计此刻仍需所有者处理的动作、草稿、阻塞事件、待核对投递等，按待办类型和记录 ID 去重。卡片标明“当前”，跨日仍未处理的事项继续显示 | 按类型列出事项，直接进入审批或核对 |

Go 按服务配置时区划分自然日，并随统计结果返回时区、日期范围和数据覆盖情况。卡片、图表及其明细共用统计口径和所有者权限范围。新记录在 native 调用和 OpenCode 步骤回执处采集用量，并关联至首个事件及运行尝试。采集起始日标出覆盖范围，升级前的调用没有可还原的用量。优先采用上游报告的 total，按协议处理缓存等子项，避免重复相加。没有用量数据的时段显示“未采集”；只有部分调用有回执时显示已知小计及覆盖情况，不按字符数推算。[模型适配器](../../internal/agent/model.go) · [OpenCode 执行器](../../internal/agent/opencode.go) · [OpenCode 步骤回执定义](https://github.com/anomalyco/opencode/blob/dev/packages/schema/src/v1/session.ts)

新闻统计在服务端复用新闻业务的投递标识与 Outbox 状态，核对完成时间的语义，不能确认日期的旧记录标明缺口。验收示例：一批三篇报道拆成两条消息，其中一条当天受理，另一条次日重试才受理，两天各计一条。

W1 先交付状态、真实待办及入口；W2 用回复和调用明细接通历史指标。验收覆盖跨午夜、同一回复多次投递、一轮多次模型调用和旧记录缺用量。抽选一天，逐条明细的去重回复数与首页相等，已报告用量的调用小计与趋势图一致。

## 现有 HTTP 能力与页面入口

下表作为交付清单。操作名称以用户任务呈现，同义命令共用按钮。所有写操作以 Go 回执更新状态；模型的七个工具在运行详情展示调用记录，外部动作仍通过既有权限和审批入口执行。[HTTP 实现](../../internal/agent/http.go) · [运维手册](../current/operations.md)

| 页面 / 任务 | 当前方法与路径 | 页面要支持的操作或状态 |
| --- | --- | --- |
| 首页、运行管理 | GET `/healthz`、GET `/v1/status`、POST `/v1/control` | 健康、执行器、模型、暂停、渠道连接、队列计数。暂停（含 stop 别名）和恢复，提示在途动作仍需核对 |
| 对话、事件队列 | POST `/v1/events`、GET `/v1/inbox`、POST `/v1/events/{id}/resolve` | 输入人工消息、查看合批与阻塞原因、对适用事件重试或跳过。提交返回事件 ID；会话归属和回复读取见 W2–W3 |
| 定时计划 | GET / POST `/v1/timers` | 查看、新建、修改、启停一次性和 Cron 计划，展示配置时区和下次触发时间 |
| 动作与审批 | POST `/v1/action-requests`、GET `/v1/actions`、POST `/v1/actions/{id}/decision`、POST `/v1/actions/{id}/resolve` | 发起已配置命名动作，审阅冻结参数，批准或拒绝。对 unknown 提交证据并核对成功或失败。动作选择器只读取宿主允许展示的名称 |
| 通知与投递 | GET `/v1/outbox`、POST `/v1/outbox/{id}/resolve` | 查看内容、目标、重试和回执；按后端允许的状态确认已送达、失败或允许重投。明确标出可能再次发送 |
| 新闻测试 | POST `/v1/news/test` | 在运行管理选来源、确认真实接收目标后触发，按返回的事件 ID 和 Outbox key 查看进度；提供脱敏来源和目标摘要。自动化只用替身 |
| 知识库 | GET `/v1/knowledge`、POST `/v1/knowledge/import`、POST `/v1/knowledge/{id}/remove` | 主入口「上传文件」将访问电脑上的文件保存到 Mac 服务器。可查看入库结果、归档文档；已有服务器路径导入放在高级操作，见 W4 |
| 记忆整理 | GET `/v1/status` 中的 memory、POST `/v1/memory/{op}` | 查看整理状态、候选和版本，操作 promote / discard / rollback；标明基线过期。通过定时计划设置整理 |
| 技能与规则提议 | GET `/v1/drafts`、POST `/v1/drafts/{name}/{decision}` | 查看 skill 和 identity 草稿、批准前问题、批准或填写理由驳回；正文、已生效内容和历史见 W5 |

四个业务表的现有列表各取最近 200 条。首页须区分表总数、当前列表条数和实际待处理数；需要完整待办或跨历史查询时，由 Go 按条件筛选、计数、分页。现有调用方的响应保持兼容。宿主配置、数据库和状态目录均不作为静态资源发布。

## IM 渠道管理（W1 查看，W6 管理）

首页显示当前生效渠道及连接状态，点击进入「运行管理 → 消息渠道」。企微和钉钉各有一个配置位置，同一实例一次使用一个渠道。列表分别显示凭证是否已填写、已保存的选择、运行中实际启用的渠道、连接状态和仅发现模式。保存配置与平台连接成功分别确认。[渠道选择](../../internal/agent/im.go) · [运行状态](../../internal/agent/http.go)

| 渠道 | 应用身份和凭证 | 正常接收任务所需的所有者配置 |
| --- | --- | --- |
| 企业微信 | `wecom.bot_id`、`wecom.secret` | `wecom.owner_userid` |
| 钉钉 | `dingtalk.client_id`、`dingtalk.client_secret` | `dingtalk.allowed_sender`，启用时还需 `dingtalk.enabled` |

- **添加、编辑和轮换。** 从未配置的渠道进入添加表单，已有配置可编辑身份、所有者及渠道准入设置，密钥单独替换。只读接口返回脱敏身份和密钥是否已设置，编辑其他字段时保留原密钥。凭证按已有私有配置管理，写入须校验版本、原子保存并保留其他配置段。添加、保存均不自动切换，也不向真实会话发送测试消息。
- **切换或停用。** 当前渠道由启动配置决定，修改后需重启。首版管理操作保存期望配置，并标出“待重启生效”；页面提供「重启 agentd」：说明会中止当前任务后确认一次，POST `/v1/restart` 先校验配置文件可加载，再由进程正常关闭并原地重新执行同一命令（PID 不变，终端、systemd 和容器照常托管），页面轮询到新进程加载配置后提示完成；重新连接 Go 后读取实际状态，区分“已启用但连接失败”和“尚未启用”。切换前校验目标配置完整性，展示旧渠道待处理事件、待核对动作和未决投递。旧消息保留原渠道及接收身份，换回原身份后按现有恢复语义处理；更换机器人身份时单独核对，不把旧通知发给新身份。
- **移除。** 删除前展示渠道及影响，由所有者确认。正在使用的渠道须先完成切换或停用，再清除本地凭证和专属设置；允许全部停用后继续通过 Web 管理。保留会话、审批、历史回执与核对入口。界面说明远端平台的密钥撤销需在对应管理后台办理。
- **实现与验收。** `/#im` 使用工作台的同源访问约定。GET `/v1/im` 返回脱敏配置、修订号、未结工作量和运行状态，POST 同一路径按修订号保存、选择或删除。显式 `im.provider: none` 停用两个渠道，省略时沿用旧配置的启用规则。删除本地配置时只保留原身份指纹，以便再次添加时核对未结任务的归属。用临时实例和浏览器覆盖配置并存、密钥轮换、网页重启、冲突、删除和历史任务保留。

## 回复溯源与会话（W2–W3）

- **历史基线。** 每日运行记录包含批次输入、作用域、状态，以及有记录的最终回答、通知和工具。最近对话缓存有长度上限。运行记录也会截断内容，检索和读取运行记录等操作有意省略，写入运行记录与业务事务分开。旧记录按已有证据展示，并标注「历史未记录」「内容已截断」或「来源未知」。[运行记录](../../internal/agent/memory.go) · [批次提交](../../internal/agent/inbox.go)
- **以每条可见消息为入口。** 详情分别展示回复正文、接收范围、生成方式、所属事件与会话、运行尝试、上下文来源、工具及审批和投递结果。支持一批多个输入、一次运行多条通知和同一事件多次尝试。模型最终答案、显式 send_message、渠道进度提示、审批与失败通知、定时业务推送都应能定位。宿主提示展示触发规则；业务生成的消息展示业务输入及可用来源。外部投递内容以 Outbox 为准，平台受理和已读单独表达。
- **在使用上下文时留下凭据。** 在 native 与 OpenCode 各自构造实际输入的位置记录执行器、可确认的模型、历史消息标识，以及当时载入的规则、记忆、知识索引、技能目录及版本。按步记录工具实际读到的文档版本、范围、检索命中的引用和必要的脱敏摘录。详情区分「随请求提供」「工具实际返回」「回复明确引用」。保留看得见的依据，不推测模型内部思考，也不用今天的文件冒充当时的内容。对外部执行器未报告的细节标注可见范围。引用元数据避免被后续检索重复命中。
- **关联与恢复。** 由宿主产生稳定的会话、运行尝试和回复标识，引用原有事件、动作和通知键。新生成的用户可见回复须能按稳定标识读回当时的完整可展示正文（按所有者权限脱敏），列表仅取摘要。浏览器可见的已提交答案和它的依据须有持久引用。设计时明确提交点与崩溃恢复：先持久化必要证据，再在既有业务提交边界确认关联；重放不重复展示或再次投递。对历史缺口独立标记。新记录的上下文按作用域脱敏、限量、去重；保留周期和过期引用的显示在 W2 定稿。新增运行时路径先更新[路径约定](90-convention-storage-layout.md)，遵循四表预算。
- **查询与阅读。** 增加所有者专用的会话列表、按会话分页的时间线、按稳定标识查询单次运行和单条回复的只读接口。Go 先按授权范围和日期扫描，再支持关键词、渠道、角色、服务对象、会话、状态及“有审批/有异常”筛选。游标分页有扫描上限并能继续，覆盖跨日、超过 200 条、同时有新记录和旧数据缺字段等情况。默认摘要，按需展开上下文；能从通知反查会话，也能从回复打开具体动作或文档版本。浏览器权限与模型工具的群聊、外发限制分别执行。
- **对话。** 复用 Inbox 排队和权限审批，为 Web 会话补充稳定归属、按该会话选择历史、限制合批并关联回复。当前普通 API 消息、定时事件使用 local 作用域，不能把全局本地历史直接显示为老板的私人对话。支持新建会话、继续追问、恢复历史，发送用稳定幂等键。页面分别显示已入队、处理中、待审批、完成或失败。刷新后按会话游标补读；首版轮询即够。普通网页回答只回原会话，另行请求的外发走 Outbox。旧 CLI、IM 消息及其去重和投递语义保持兼容。

W3 的网页会话由 Go 分配标识，第一条消息入 Inbox 后出现在会话列表中。连续消息仅在同一会话的固定窗口内合批，回复显示在该批最后一条输入之后。网页历史从该会话已提交的输入和回复恢复，OpenCode 按会话选择独立会话 ID。审批决定、过期和人工核对在创建续跑事件时继承原事件的网页会话。网页审批在对话中打开，普通回答写入回复账本，显式外发沿用 Outbox。发送未获回执时用原键查询或重试；浏览器刷新后可继续核对。[工作台使用说明](../../web/README.md)

## 知识库文件上传与检索（W4）

工作台的「导入知识」默认打开访问电脑的文件选择器。用户选择文件后，浏览器把文件内容上传给 Mac 上的 agentd，由服务端决定保存位置。用户无须知道服务器路径。成功入库的文件复用[当前知识库存储布局](90-convention-storage-layout.md)，以下路径均相对 agentd 的状态根目录（`-root`）：

| 内容 | Mac 服务器保存位置 | 用途 |
| --- | --- | --- |
| 上传的原始文件 | `data/knowledge/raw/<doc_id><扩展名>` | 保留原始字节；清单关联文档 ID、来源和内容哈希 |
| 可检索的正文 | `workspace/knowledge/md/<doc_id>.md` | 供 agentd 的 `search` 命中内容，再用 `read_file` 读取上下文 |
| 资料目录与清单 | `workspace/knowledge/INDEX.md`、`data/knowledge/manifest.json` | 前者供模型发现资料，后者记录导入元数据 |

网页收到完整文件的传输回执后显示「处理中」；只有服务端确认原件、正文和索引均已保存，才显示「已入库，可检索」。

1. 默认提供「从这台电脑上传」，原生文件选择支持键盘和多选，拖放作为补充。「从服务器路径导入」另设入口，明确路径由服务端解释。选择前显示支持的格式和大小；当前原件上限 50 MiB、转换后 Markdown 上限 1 MiB。Markdown、纯文本可直接导入，其他已支持格式根据服务端转换器配置展示可用性。[现有导入器](../../internal/agent/knowledge.go) · [GOV.UK 文件上传设计](https://design-system.service.gov.uk/components/file-upload/)
2. 选中后逐项显示文件名、大小和校验结果，允许移除，再提交。每项区分等待、传输、服务器处理中、已入库、未变化和失败。提供上传阶段取消、失败原因和只重试失败项。传输百分比只反映已发送字节；转换时显示阶段状态。刷新后可查看服务端已接收的批次和结果。传输断开先核对服务端记录，再决定重传。[浏览器上传进度](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest/upload)
3. 增加受保护的 multipart 上传与批次状态接口，按流接收，限制每文件、每批总量和文件数。仅上传入口使用独立请求体及超时预算，结合现有服务器读超时验证慢速上传。校验实际内容、格式及文件名，私有临时文件由宿主命名，完成、失败和取消后清理。服务器只接受完整文件进入现有沙箱转换、归档和索引流程；保留单次导入互斥和忙时反馈。[OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
4. 现有文档 ID 来源于服务器源路径。上传需独立于临时路径的稳定来源标识和请求键。重复提交同一来源同一内容返回原结果；同名不同内容由用户明确选择更新已有文档或作为新文档。上传选集不能触发目录镜像的“缺失即归档”。已有服务器路径和清单 ID 继续有效。
5. 以「电脑 A 上传含唯一短语的文件到 Mac B」验收：核对 B 上原件的哈希与所选文件一致；关闭上传页面、移走 A 上的源文件并重启 agentd 后，仍能在 B 检索到该短语、打开对应文档正文。再测转换器缺失、超限、同名、重复上传、部分失败、转换中断及重启恢复。工作台沿用可信网络的同源入口，Go 默认监听回环地址。自动化验收使用独立浏览器会话与临时服务端状态目录，另测重启恢复。

## 记忆与技能如何观察（W5）

- **当前有效内容。** 提供受限的列表和详情接口，浏览 MEMORY.md 索引、关联 notes、当前身份规则、有效技能正文。技能标明内置或工作区来源，并按实际覆盖顺序呈现。支持从知识条目查看导入版本，也能从有证据的运行回到当时用到的内容。
- **变化及依据。** 按时间展示普通运行写记忆、整理产生的新增/修改/退役条目、候选与当前版本差异、提升/丢弃/回滚，以及技能和规则草稿的批准/驳回。每项尽量链接来源运行、原文证据、操作人或触发方式。普通写入只有当前文件或工具回执时，明确可用范围；后续写入记录可对比的版本引用。审核在差异旁进行，继续调用原闸门，遇到并发修改重新读取。
- **评估视图。** 按时间段回答“新增了哪些经确认的事实、哪些技能开始生效、在哪些运行中实际读取过、还有哪些失败待核对”。指标可点回明细，有未知项时标注覆盖范围。条目增加仅说明积累增加，能力是否提升留给路线 C5 的固定任务评测。

### 手动 Dreaming 与人工修订

「Dreaming（记忆整理）」是现有 consolidation 的工作台名称。首版在「记忆与技能」提供「立即整理」，与定时触发共用 Inbox、strong 档执行、候选检查、提升及回滚逻辑。定时整理使用 `strong_model`，网页可选择已启用的默认强模型和服务端 `dream_models` 中明确配置的服务。按次选择绑定模型名与端点版本。[执行入口](../../internal/agent/loop.go) · [整理决定](../../internal/agent/consolidation.go)

1. **发起一次。** 所有者从服务端已配置且获准处理整理数据的模型中选择（例如 OpenAI 或 Gemini），看到具体模型及可发送的数据范围，再提交一次。后端绑定本次模型配置标识，保存实际模型与运行 ID，重试沿用原选择；旧单模型配置仍可用，定时整理沿用原默认项。不可用时显示原因，不自动换模型。密钥留在服务端，保留 owner/local 运行记录的外发限制。手动触发不改定时计划，幂等键防重复入队，定时与手动操作共用整理互斥和待审候选规则。
2. **看进展。** 首版按运行 ID 短轮询，以服务端记录显示排队、整理中、检查及最终结果。候选文件每次完整写入后显示已保存的差异，可从变更查看可用证据。记忆在提升后才更新“当前生效”视图；技能显示“草稿待审”，批准后才进入有效目录。无变化、因基线冲突待处理、跳过或失败各有明确结果。刷新后可接着看同一次运行。
3. **人工改记忆。** 所有者可以编辑 MEMORY.md 或具体笔记，预览差异后保存。Go 复用工作区写入校验和索引上限，按打开时的版本哈希检测并发修改。保存前保留可恢复版本，记录修改人、时间、差异及新版本；来源标为人工修订。整理候选基线过期时不得覆盖人工改动。
4. **人工改技能。** 从现行技能发起修订，或编辑待审草稿。预览与基线的差异，校验名称、描述、文件及容量后，由所有者批准发布。内置技能通过工作区同名版本覆盖。草稿和发布都核对基线；提供查看旧版本和恢复为新修订的入口，历史运行仍引用当时的版本。[技能审批](../../internal/agent/gate.go)
5. **端到端验收。** 用两个本地强模型替身验证按次选择，重复点击只产生一次任务，自动与手动整理不会同时写候选。验证页面可见候选到生效的变化、技能批准前后差异、无变化和失败。用两个标签页交错编辑同一条目，后提交者能看到冲突并保留编辑内容；人工修订可追溯和恢复。

工作台的浏览器回归还覆盖旧页面脚本缺失后的重新加载、服务端本地时区、知识库链接的前进与后退、无效上传回执的原批次重试，以及记忆修订和手动整理等待回执时的操作。用例见[工作台浏览器测试](../../web/tests/workbench.spec.mjs)。

W2 在运行开始时写入稳定尝试 ID，结束时在同一业务事务内保存脱敏证据、回复与通知关联。写证据失败会回滚本次业务提交并暂停，重启后保留中断尝试并按 Inbox 原有恢复规则处理。按步证据位于私有 SQLite 中，每次尝试最多留存 256 个来源、512 条请求或工具等引用记录（每次请求关联该步实际提交的来源）、512 KiB 摘录，每个来源的摘录最多 16 KiB；截断和省略在详情中标明。已完成事件按最后一次运行时间保留 30 天上下文快照，清理后保留运行索引和已有回执；未解决的死信保留其快照。旧快照沿用已记录的步骤。文件可用时保留当时的 SHA-256，检索命中保留当时返回的片段和偏移。旧归档没有版本时展示缺口。构建、隔离预览和只读接口见[工作台使用说明](../../web/README.md)。

每次交付更新本页、[开发路线](91-convention-roadmap.md)和已落地的操作说明。每项先用临时数据完成一条从页面到 Go 再读回的真实路径，执行类型检查、ESLint、生产构建和对应 Playwright 用例。Go 改动按仓库约定运行 test、vet，涉及并发或取消时加跑 race。验收使用中文界面、键盘、窄屏和真实浏览器。外部模型、平台消息与真实订阅者测试沿用仓库现有的确认边界。
