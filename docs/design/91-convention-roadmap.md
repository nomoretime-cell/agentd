## 2. 总路线

```text
阶段 A  单角色记忆闭环          A1 .agentd/ ─► A2 作用域字段 ─► A3 强模型 ─► A4 整理安全 ─► A5 启用整理
                                                                 ▲
                                                   决策 D1 ✅（群聊数据不外发）
阶段 B  沉淀做法与外部知识      B0 检索 ─► B1 skill 草稿 + 闸门 ─► B2 knowledge 导入
                                  ▲
                       决策 D2 ✅（search 为第 7 个工具，不加表）
阶段 C  公司多角色（第三阶段）  C1 第三阶段设计 ─► C2 worker 并发 ─► C3 角色分目录 ─► C4 付费等级与提升闸门
                                       └──────────────► C5 评测闭环
阶段 D  按需增强                向量检索、回归探针、verify 闸门、模型升级后全量重建
```

阶段之间按顺序进行；阶段内部按箭头的依赖顺序。阶段 D 的各项在出现实际需要时再做。

**单所有者工作台（W1–W5 已完成，W6 已实现 IM 渠道管理）。** 作为阶段 B 之后的独立交付线，先让所有者核对现有 agent 的回复、动作和积累，再扩展到多角色。W1 正式服务同端口直接进入首页、查看待办与审批 → W2 回复溯源及每日回复、token、新闻推送统计 → W3 对话；W4 跨机器上传依赖 W1 和 B2，W5 记忆与技能浏览、手动 Dreaming 及人工修订依赖 W2 和 A4/B1，W6 已实现 IM 配置管理：保存、切换、停用与删除写入配置文件，在页面点「重启 agentd」后生效（进程原地重新执行，配置无法加载时拒绝重启）。2026-11-27 曾加入同进程即时切换，因连接交接与停工协调的代价远高于一次整进程重启，同日撤回，改为网页重启（见对应提交说明）。运行状态页已提供运行中二进制的 Git 提交号，供发布后核对。工作记录、对话、消息发送记录及其跨页入口已统一界面术语。知识上传集中在知识库，首页待办保留筛选并可直达对应草稿审核项。对话按消息显示排队与处理进度，状态行可追溯本次处理依据。回复气泡支持 Markdown 排版，历史与溯源沿用同一份原文。其余操作入口及整体验收待完成。接口覆盖表、后端缺口和各项完成条件见[所有者工作台开发计划](92-convention-owner-workbench.md)。2026-11-25 已按 AGENTS.md 对 W1–W6 逐个提交复审并修正（548ba42 至 e4f3894），暂缓事项及理由记在各复审提交说明中。W1–W3 发布修订按服务端状态审批，在浏览器存储不可写时核对发送回执，并记录每次请求实际使用的上下文；已完成事件的快照保留 30 天。

## 3. 阶段 A：单角色记忆闭环

目标：agent 能安全地"事后复盘"。完成后整理定时器可以启用。

| 项 | 内容 | 依赖 | 完成标准 | 设计 |
| --- | --- | --- | --- | --- |
| ✅ **A1** 引入 `.agentd/`（2026-11-23） | `-root` 默认 `.agentd`；默认内容 `go:embed`；路径改为相对工作目录；检测到旧布局时停止启动并提示，不自动搬数据 | 无 | 新实例只在 `.agentd/` 下产生文件；旧实例用 `-root .` 行为不变 | [路径约定](90-convention-storage-layout.md) 第 7 节第 1 步 |
| ✅ **A2** 运行记录加作用域字段（2026-11-23） | 每条记录加 `role`（固定 `default`）、`principal`、`conversation` | 无 | 新记录都带这三个字段；已有字段与格式不变 | 同上第 2 步 |
| ✅ **A3** 模型分级（2a，2026-11-23） | 配置 `strong` 档；整理等关键动作由代码绑定 strong 档，不回退；数据外发需显式开启 | D1 | strong 档未配置或失败时整理不执行；有测试证明不会回退到 default | [记忆设计](02-stage-2-memory.md#关键动作与模型分级) |
| ✅ **A4** 整理安全机制（2b，2026-11-23） | 候选版本 → 代码检查（证据逐字存在、无静默删除、上限、改动量阈值）→ 提升并保留旧版本；整理指标；改 `memory-consolidation/SKILL.md`（evidence、`## 历史`、规则型条目只提议） | A1 | 任一检查不过时当前记忆不变；可回滚到上一版本 | [记忆设计](02-stage-2-memory.md#整理的安全机制) |
| ✅ **A5** 启用整理（2026-11-23；一周运行验证待做） | README 中的整理定时器改为推荐启用 | A3、A4 | 连续运行一周，整理指标无异常 | |

**为什么 A1、A2 排在最前：** A1 定下文件位置，A4 新增的候选版本和指标文件直接放在正确位置，不用迁移两次。A2 改的是原始数据：原始记录缺的字段以后补不回来，晚做一天，就多一天的记录只能归入 `_legacy`。

## 5. 阶段 C：公司多角色（第三阶段）

目标：一台机器按付费情况服务多个角色，角色间默认隔离。

| 项 | 内容 | 依赖 | 说明 |
| --- | --- | --- | --- |
| **C1** 第三阶段设计文档 | 角色与身份、付费等级、知识集合权限、跨角色提升闸门 | 阶段 B | 新建 `design/03-stage-3-*.md`；作用域决策已写在[记忆设计](02-stage-2-memory.md#作用域权限与闸门)和[路径约定](90-convention-storage-layout.md) |
| **C2** worker 并发 | 不同角色（或服务对象）的事件可并行执行，同一会话仍串行 | C1 | 现在只有一个 worker，一个角色的慢任务会挡住所有角色 |
| **C3** 角色分目录 | 建立 `company/`、`roles/` 与虚拟路径映射，单角色内容迁入 `roles/default/` | C1 | [路径约定](90-convention-storage-layout.md) 第 7 节第 3 步 |
| **C4** 付费等级与提升闸门 | 按等级授权知识集合；跨角色提升经 strong 档审核和人工确认 | C3 | 同上第 4 步 |
| **C5** 评测闭环 | 固定任务集与评分标准，衡量 agent 行为是否变好；模型或 prompt 变更前后对比 | C1 | 对外收费后需要能证明效果；回归探针（阶段 D）可复用其任务集 |

C2 和 C5 来自 2026-11-23 的架构评估，在此之前没有进入任何计划。
