# agentd 所有者工作台

W1 提供服务和 IM 状态、四类待办、冻结参数审批与回执。动作详情链接可在刷新后直接查看。每 5 秒刷新概览，动作详情每 3 秒核对一次状态。

## 工作概览

首页按服务时区显示近 7 或 30 天的活动。点今日卡片或图中的日期可读对应明细。「回复」统计已成功提交的本地消息最终回答和返回原 IM 会话的正式消息，按回复键计一次。「Token 用量」含普通、强模型及新闻翻译调用，回执缺总量时标明已报告的调用数。OpenCode 使用步骤回执，外部执行器未报告的内部调用不可见。「新闻推送」按一条正式 Outbox 消息首次确认送达的日期计数，区分渠道回执和人工核对。当天的待办独立按当前状态刷新。

本版首次打开状态库时事务迁移至 schema v4。需要旧版本回退能力时，升级前备份整个状态根目录，旧二进制要求使用迁移前的副本。历史正文仍可浏览，缺失的确认时间和用量不回填。

## 会话与运行

打开「会话与运行」可切换运行、会话及通知投递三个视图。运行与会话默认查询最近 7 个服务时区自然日，可选最多 31 天，按输入、回答或通知关键词、渠道、角色、服务对象、会话、状态、审批或异常筛选。会话按已读取的页累计；点击一项查看该作用域的时间线。本地 API 和定时任务沿用已有 local 作用域。

从运行详情点「查看完整回复」核对已提交的正文。从「通知投递」打开消息，查看实际 Outbox 内容、接收范围、当前状态、确认方式，并回到产生它的尝试。进度提示属于接收事件，可查看这个事件随后产生的尝试。点击「上下文依据」中的文档或工具条目，可查当时的脱敏摘录、可用版本、字节位置和步骤。OpenCode 的内部历史仅能看到宿主传入或执行器回报的部分。旧记录按归档内容展示，缺少的版本和用量会标明。

| 所有者只读接口 | 内容 |
| --- | --- |
| `GET /v1/runs`、`GET /v1/conversations` | 支持 `from`、`to`、`q`、`channel`、`role`、`principal`、`conversation`、`status`、`flag=approval/error`、`event`、`attempt`。续页沿用日期范围和筛选并带上 `next` 作为 `cursor`。每页最多 20 次运行，扫描预算用尽时空页也可能有后续游标。 |
| `GET /v1/runs/{id}` | 新尝试使用首个事件 ID 和尝试 ID，两者以 `~` 连接。旧链接沿用归档的日期与字节偏移。 |
| `GET /v1/deliveries`、`GET /v1/replies/{id}` | 按游标分页列出投递摘要，按返回的消息 ID 读取正文与关联。脱敏后的完整 Outbox 正文按需读取。 |

## 对话

打开「对话」，点「新建会话」并发送第一条消息。每个会话有独立链接，第一条消息的开头用作会话列表标题。服务端按事件顺序展示排队、执行、回复和审批结果，运行依据可从每轮对话打开。审批直接在对话里处理，刷新页面后仍可继续追问。最近记录每两秒核对一次，「读取更早消息」向前翻页。正式会话调用当前实例配置的模型。

`POST /v1/chats` 接受空 JSON 对象，返回会话 ID。向 `/v1/chats/{id}/messages` POST `{"key":"客户端发送编号","text":"消息正文"}`，返回事件 ID 和是否首次插入。重试时复用原编号和正文；修改同一编号的正文会收到 409。浏览器只在当前标签页的 sessionStorage 暂存待核对的发送编号，取得回执后清除。已有会话与消息通过 GET 分页读取，响应中的 `next` 可作为 `cursor` 继续向前读取。

## 构建与接入

`make release` 构建带静态资源的 `bin/agentd-web`。与原二进制使用相同的 `-config` 和 `-root`。一个状态根目录只能被一个运行实例拥有。普通 `make build`、`make test` 和 `make vet` 继续只依赖 Go。

浏览器打开与配置一致的地址（默认 `http://127.0.0.1:8090`）。经 SSH 转发到不同端口或通过反向代理访问时，在该实例的配置中将 `web_origin` 设为浏览器地址栏确切的来源，例如 `https://agent.example.com` 或可信网络的 `http://192.0.2.10`，重启后生效。代理原样转发 Origin。页面直接打开，无需所有者令牌。能够访问该入口的人均可查看历史、对话或审批动作，请将入口限定在可信网络。工作台和真实模型会话共用同一个 agentd 实例。

开发时在单独的开发实例配置 `web_origin: "http://127.0.0.1:5173"`。启动 Go 服务后运行 `pnpm --dir web dev`，Vite 将 /v1 请求转到 127.0.0.1:8090。用独立状态目录和本地替身验证审批。

## 验证

```sh
pnpm --dir web typecheck
pnpm --dir web lint
make release
pnpm --dir web exec playwright install chromium
pnpm --dir web test:e2e
```

本机已有 Google Chrome 时可用 `PLAYWRIGHT_CHANNEL=chrome pnpm --dir web test:e2e`。
